# PRD: 스타트업 막내 개발자로 환생했습니다

> 콘셉트: 개발자 인생 1회차 · 작성일: 2026-10-08 · 상태: 초안 v0.1 · 레퍼런스: [80억 분의 1 분석](./1in8b_reference_analysis.md)

## 표기 규칙

| 표시 | 뜻 |
|---|---|
| **[확정]** | 사용자가 정한 것. 바꾸려면 사용자 확인이 필요하다. |
| **[제안]** | 작성자(Claude)의 제안. 아직 정해지지 않았다. |
| **[예시]** | 사용자가 고른 장면 속 숫자와 문구. 구조는 확정이고 값은 예시다. |

## 1. 한 줄 요약

**[확정]** 무작위 배경의 개발자로 태어나 커리어 한 사이클(입사부터 은퇴 또는 조기 종료까지)을 짧게 살아 보는 시뮬레이션 게임. 연차마다 카드 한 장씩 나오는 결정을 좌우로 넘기며 고르고, 끝에는 은퇴 화면에 내 인생 기록이 남는다.

**[확정]** 게임 이름: "스타트업 막내 개발자로 환생했습니다"

## 2. 목표와 비목표

### 목표

| # | 목표 | 상태 |
|---|---|---|
| G1 | **한 사이클을 끝까지 해 보고 싶은 게임.** 한 번 시작하면 은퇴나 조기 종료까지 간다. | [확정] |
| G2 | **다시 돌려 보고 싶은 게임.** 앞 회차에서 얻은 지식이 다음 회차의 선택지가 된다. | [확정] |
| G3 | **짬짬이 학습.** 플레이하는 동안 기술 개념을 조금씩 익힌다. | [확정] |
| G4 | 선택과 결과의 인과가 보인다. "이 선택 때문에 지금 이렇게 됐다"를 엔딩에서 확인한다. 레퍼런스의 약점을 메우는 장치다. | [제안] (엔딩의 인과 타임라인은 [확정]) |

### 비목표 (첫 버전)

| 항목 | 이유 | 상태 |
|---|---|---|
| 모바일 앱 | 플랫폼은 데스크톱 웹 우선으로 정했다. | [확정]에서 도출 |
| 카드 실시간 AI 생성 | 콘텐츠는 "제일 간편한 방법으로 시작"하기로 했다. | [제안] |
| 이미지 공유 카드, 개인 결과 페이지, 명예의 전당 | 공유는 문구 복사와 게임 링크로 정했다. 서버가 필요 없다. | [제안] (공유 방식은 [확정]) |
| 로그인, 서버 저장, 랭킹 | 1일 제작 범위를 넘는다. | [제안] |
| 실제 통계 기반 리얼리즘 (레퍼런스식 확률 엔진) | 이 게임의 축은 통계가 아니라 기술 판단의 인과와 회차 간 해금이다. | [제안] |
| 커리어·처세 조언 | 상황 카드에는 정답도 해설도 두지 않는다. | [제안] |
| 구간 압축 모드 (몇 년을 한 장으로 묶기) | 속도 조절 방식 중 고르지 않았다. | [확정] (선택 안 함) |
| 레퍼런스의 동기 비교, 성찰 멈춤, 실시간 시간 흐름 | 짧은 카드형 루프에 집중한다. | [제안] |

## 3. 대상

- **[확정]** 현업 개발자 전체(연차 무관).
- **[확정]** 짬짬이 학습이 되어야 한다.
- **[제안]** 연차마다 다른 재미를 기대한다.
  - 주니어: 해설과 개념 도감에서 배운다.
  - 시니어: "겪어 본 장면"에 공감하고 인과 타임라인을 보며 웃는다.
  - 판 안 퀴즈 카드는 연차와 상관없이 가볍게 즐기는 학습 장치다.

## 4. 플랫폼

- **[확정]** 데스크톱 웹 우선.
- **[제안]** 조작과 저장
  - 마우스: 카드를 드래그하거나 좌우 버튼을 클릭한다.
  - 키보드: ← → 로 고르고, 해금된 세 번째 선택지는 ↓ 로 고른다.
  - 모바일: 터치 스와이프로 동작은 하지만 첫 버전에서 다듬지 않는다.
  - 저장: 로그인 없이 브라우저 localStorage에 한다. 진행 중인 판은 이어서 할 수 있다.

## 5. 핵심 루프 (한 사이클 흐름)

**[확정]** 큰 흐름: 무작위 출발 → 연차마다 카드 1장 결정 → 은퇴(30년차) 또는 조기 종료 → 엔딩 → 다시 하기.

**[제안]** 세부 흐름:

```
[타이틀]  새 인생 시작 / 개념 도감
   ↓
[출발 카드]  무작위 시작 속성 공개 (배경 · 회사 · 스택)  →  게이지 초기값
   ↓
[연차 루프] 1년차 ~ 30년차
   ├ 카드 등장 (기술 판단 / 상황 / 이벤트 중 하나)
   ├ ← / → 로 선택 (해금 개념이 있으면 ↓ 세 번째 선택지)
   ├ 결과 표시: 게이지 변화 + 결과 문구 (+ 기술 판단 카드면 해설 한 줄)
   ├ 플래그 기록 (뒤 카드의 결과를 바꿀 수 있음)
   └ 종료 판정: 체력 0 / 신뢰 0 / 기술부채 최대 → 조기 종료
   ↓
[엔딩]  인과 타임라인 · 학습한 내용 요약 · 오늘의 개념 · 문구 복사 · 다시 하기
   ↓
[다음 회차]  이번에 얻은 개념이 세 번째 선택지를 연다
```

**[확정]** 길이: 30년차에 은퇴한다. 카드는 연차마다 한 장이라 한 판에 최대 30장이다.

**[확정]** 속도 조절 기능 3가지:

| 기능 | [제안] 동작 |
|---|---|
| 평범한 해 자동 넘김 | 켜 두면 상황 카드는 그 카드의 "무난한 쪽"을 자동으로 고르고 결과 한 줄만 기록에 남긴다. 기술 판단·이벤트·퀴즈 카드에서는 멈춘다. 발동할 이벤트가 없는 해도 자동으로 넘긴다. |
| 배속 (연출 속도) | 카드 등장, 결과 애니메이션, 텍스트 표시를 1× / 2× / 4×로 바꾼다. 결정 수는 그대로다. |
| 자동 결정 모드 | 카드마다 몇 초 카운트다운 뒤 기본 선택지로 넘어간다. 클릭하거나 키를 누르면 멈춘다. 자동으로 고른 선택은 타임라인에 "자동"으로 표시한다. |

## 6. 게임 시스템

### 6.1 시작 속성

- **[확정]** 무작위 배경의 개발자로 태어난다.
- **[제안]** 무작위 항목:
  - 배경: 전공 / 비전공 국비 / 독학 / 부트캠프. 시작 게이지에 작은 보정을 주고 카드 문구 일부를 바꾼다.
  - 첫 회사: 첫 버전은 **스타트업으로 고정**한다. 게임 이름과 맞고, 카드 30장 범위에서 회사별 분기를 만들 여유가 없다. 이후 SI / 대기업 / 에이전시로 넓힌다.
  - 스택: 기술 이름만 바뀌고 개념은 같다. 예를 들어 React + Express ↔ Vue + Spring은 같은 카드에서 단어만 바뀐다.
- **[예시]** 원안 시작 조건: 비전공 · 국비 6개월 · 직원 12명 스타트업 · React + Express

### 6.2 게이지

**[확정]** 연봉 / 신뢰 / 기술부채 / 체력, 4개.

| 게이지 | [제안] 범위 | [제안] 역할 |
|---|---|---|
| 연봉 | 금액(만 원) | 쌓이는 점수. 조기 종료 조건이 아니다. |
| 신뢰 | 0–100 | 0이 되면 권고사직 |
| 체력 | 0–100 | 0이 되면 번아웃 |
| 기술부채 | 0–100 | 100이 되면 서비스 붕괴 |

**[제안]** 카드 결과를 보여 줄 때 바뀐 게이지만 강조한다(예: "신뢰 −5"). 어떤 숫자가 왜 움직였는지 바로 보이게 하려는 것이다.

### 6.3 카드

**[확정]** 원안 3종을 쓴다.

| 종류 | 설명 | 해설 |
|---|---|---|
| 기술 판단 카드 | 배포, 테스트, 캐시처럼 동작 원리로 결과를 설명할 수 있는 카드 | 있음 |
| 상황 카드 | 이직 제안, 야근처럼 정답이 없는 카드 | 없음 |
| 이벤트 카드 | 늦게 터지는 결과가 발동하는 카드 | [제안] 발동 원인을 한 줄로 밝힘 |

**[확정]** 종류를 나눈 이유: 커리어 상황 카드는 정답이 애매해져서 처세 조언으로 흐르기 쉽다.

**[확정]** 판 안 퀴즈 카드를 넣는다(학습 장치, 6.8 참고).
- **[제안]** 퀴즈 카드는 정답이 있는 "기술 판단 카드의 한 형태"로 본다. 예: 동료나 면접관이 개념을 묻고, 두세 개 답 중 하나를 고른다. 맞히면 신뢰나 연봉이 조금 오르고, 틀려도 해설을 보여 준다.

**[확정]** 원안 예시 턴 (구조 확정, 숫자와 문구는 [예시]):

> **3년차 · CTO 카드**
> "금요일 오후 5시예요. 결제 모듈 핫픽스 끝났는데, 지금 배포할까요?"
>
> - **← 월요일 오전에 배포:** 주말 동안 결제 오류 문의 47건. 신뢰 −5, 체력 유지
> - **지금 배포 →:** 1년차 때 "테스트는 나중에" 카드를 골랐기 때문에 22:40 결제 실패율 18%, 주말 내내 장애 대응. 체력 −30, 신뢰 −10
>   - 해설: "금요일이라서 위험한 게 아니라, 문제가 생겼을 때 되돌릴 수단이 없어서 위험합니다."
> - **↓ (이전 회차에서 "기능 플래그"를 얻었다면):** 기능 플래그 뒤에 숨겨 지금 배포하고 결제 1%에만 켜기 → 오류를 10분 만에 발견하고 플래그를 끈다. 신뢰 +5, 기술부채 +1

**[제안]** 카드 데이터 구조(요약):

```
Card {
  id, type: tech | situation | event | quiz,
  years: [min, max],              // 등장 가능 연차
  speaker, prompt,
  requires?: flag[],              // 이벤트 카드: 이 플래그가 있을 때만 등장
  left / right / down?: Option    // down은 requiresConcept가 있을 때만
}
Option {
  label, effects: {salary, trust, debt, stamina},
  setFlags?: flag[],
  result, resultByFlag?: {flag: result},  // 지연 결과로 결과 문구·효과가 갈림
  explanation?,                    // 기술 판단 카드만
  grantsConcept?, requiresConcept?
}
```

### 6.4 지연 결과

- **[확정]** 앞에서 고른 선택이 몇 년 뒤 결과를 바꾼다. 원안에서는 1년차 "테스트는 나중에" 때문에 3년차 금요일 배포가 장애로 이어진다.
- **[제안]** 선택은 플래그(예: `skipped-tests`)를 남긴다. 지연 결과는 두 가지 방식으로 드러난다.
  1. 뒤 카드의 **결과 분기**(`resultByFlag`). 원안의 금요일 배포 카드가 이 방식이다.
  2. **이벤트 카드 발동**(`requires`). 플래그가 있을 때만 그 해에 이벤트 카드가 나오고, 없으면 그 해는 "평범한 해"로 자동으로 넘어간다.
- **[제안]** 지연 결과가 터지면 결과 화면에 원인 선택을 함께 보여 준다(예: "1년차의 '테스트는 나중에' 때문에"). 같은 연결이 엔딩의 인과 타임라인에서 선으로 이어진다.

### 6.5 종료 조건

- **[확정]** 30년차에 은퇴하거나 그 전에 조기 종료된다.
- **[제안]** 조기 종료 조건:

| 조건 | 종료 |
|---|---|
| 체력 0 | 번아웃 |
| 신뢰 0 | 권고사직 |
| 기술부채 100 | 서비스 붕괴 |

### 6.6 엔딩

**[확정]** 은퇴나 조기 종료 화면에 보여 줄 것:

| 항목 | [제안] 세부 |
|---|---|
| 인과 타임라인 | 연차별 선택을 세로 목록으로 보여 준다. 지연 결과가 있으면 원인 선택과 결과를 선으로 잇는다. 자동으로 고른 선택은 흐리게 표시한다. |
| 학습한 내용 리스트 요약 | 이번 판에서 만난 개념과 해설, 퀴즈 결과(맞힘/틀림)를 목록으로 보여 준다. |
| 오늘의 개념 | 이번 판에 가장 큰 영향을 준 개념 하나를 강조한다(예: "당신의 장애 2회는 기능 플래그로 막을 수 있었습니다"). |

**[제안]** 엔딩에 함께 둘 것:
- 맨 위에 종료 사유 한 줄(예: "17년차, 번아웃")
- 이번에 새로 얻은 개념
- [다시 하기], [개념 도감] 버튼

### 6.7 공유

- **[확정]** 공유는 문구 복사와 게임 링크로 한다. 버튼 하나로 클립보드에 복사한다.
- **[제안]** 문구 예: "비전공 국비 출신, 17년차에 번아웃. 장애 3회. 얻은 개념: 기능 플래그 · 자동화 테스트 → (게임 링크)"
  - 원래 제안에 있던 "결정적 순간" 한 줄은 엔딩 항목으로 고르지 않아서 문구 내용은 열린 질문으로 남긴다.

### 6.8 회차 간 해금과 학습

- **[확정]** 앞 회차에서 얻은 개념 카드가 다음 회차에서 세 번째 선택지(↓)를 연다.
- **[확정]** 학습 장치 3가지:

| 장치 | [제안] 세부 |
|---|---|
| 개념 도감 | 얻은 개념 카드를 모아 보는 화면. 카드 뒷면에 3줄 설명, 작은 예시, 더 읽을 거리 링크. 타이틀과 엔딩에서 연다. |
| 판 안 퀴즈 카드 | 6.3 참고 |
| 엔딩의 오늘의 개념 | 6.6 참고 |

- **[확정]** 퀴즈를 맞혀 개념을 바로 해금하는 방식은 고르지 않았다. 해금은 플레이로 얻는다.
- **[제안]** 개념은 그 개념과 연결된 지연 결과를 겪었을 때 얻는다(예: 되돌릴 수단 없이 장애를 겪으면 "기능 플래그"). 얻은 개념은 브라우저에 저장되고 다음 회차부터 쓸 수 있다.

## 9. 성공 기준

**[확정]** 첫 버전에서 볼 지표 3가지:

| 지표 | 정의 | [제안] 목표 |
|---|---|---|
| 완주율 | 시작한 사람 중 한 사이클(은퇴 또는 조기 종료)을 끝까지 간 비율 | 70% 이상 |
| 2회차 시작률 | 첫 판을 끝낸 사람 중 누가 시키지 않아도 다시 시작한 비율 | 50% 이상 |
| 학습 체감 | 플레이 후 "새로 알게 된 개념이 있다"고 답한 비율. 판 안 퀴즈 정답률을 보조 지표로 본다. | 50% 이상 |

**[제안]** 측정 방법: 동료·지인 개발자 10명 안팎에게 링크를 주고 관찰한 뒤 한 문항 설문을 받는다. 1일 제작이라 분석 도구는 넣지 않는다. 필요하면 엔딩 도달과 다시 하기 클릭 정도만 간단히 집계한다.
